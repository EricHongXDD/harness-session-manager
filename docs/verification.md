# Harness Session Manager 验证记录

## 0.3.0 工作区展示、直接隐藏和永久删除

当前版本隐藏／恢复不生成 ZIP，不再弹隐藏和恢复隐藏的确认框；恢复完成后清理隐藏容器和记录，并仅按同一隐藏记录的 ID、来源、时间和成员清理旧自动 ZIP。独立手动 ZIP 保留。对话按 Harness 工作区登记顺序、名称和完整路径分组，归档与子会话保留可见，每组默认显示 6 条，可展开。

新增前端交互逻辑测试（最小 DOM 替身）验证直接隐藏不弹确认、不调用备份；Harness 退出提示出现在 `alertdialog`，关闭后页面保留错误；永久删除取消不提交，确认后才提交预览令牌；分组直接显示完整路径。Node 共 8 项测试通过，此测试不代替真实窗口布局验收。

Go 测试验证：隐藏时图片缺失也能移动原会话；隐藏和恢复不新增 ZIP；恢复后无隐藏残留；清理旧自动 ZIP 时保留手动备份；永久删除须有有效预览，范围变更、数据变更、过期令牌或 Harness 运行时拒绝；删除包含父子组，保留其他会话共享图片；工作区删除包含隐藏对话、清理归档／置顶登记，并保留真实合成代码文件夹中的哨兵文件；空工作区可删除；其他工作区和未知登记字段保留。

最终 Windows EXE 的固定合成来源以真实应用 API 验证 3 → 隐藏后 2 → 恢复后 3 → ZIP 恢复后 3 → 永久删除后 2 → 手动 ZIP 恢复后 3 → 删除另一工作区后 2。每个阶段由 Harness 原始持久化和 SQLite 查询库核对；删除工作区后的登记通过 Harness 原始 schema，恢复的图片仍通过原生读取校验。全过程仅产生一次显式手动 ZIP，隐藏区恢复后为空，最终空间统计与独立元数据枚举相符。

`go vet`、Go 全套测试、Node 前端测试和 Windows 生产构建通过。本轮未操作真实数据或原生桌面窗口，没有上传。

## 0.2.0 标题、图片与 ZIP 导入

本轮使用合成会话验证最新 `session/title` 用户备注覆盖旧缓存、首次用户文本回退、消息图片引用及 PNG 预览、图片缺失／篡改拒绝、共享图片去重、带图 ZIP 导入另一份空来源后恢复、重复导入和重复恢复、图片冲突时不写入会话、缺少图片清单和重复清单的 ZIP 拒绝。导入只复制到本应用备份库，不自动恢复来源；旧版备份保留兼容并显示可能缺图提示。

最终 EXE 的 `--preview` 使用固定合成来源，通过真实应用接口执行备份／隐藏／恢复。Harness 原始持久化库读取含图片和标题事件的压缩 v4 日志，原始标题折叠结果与 Harness Session Manager 一致。删除合成会话及其外置图片后，从 ZIP 恢复，Harness 原始 `readImageFile` 验证图片字节、格式、尺寸、长度和 SHA256 均通过；恢复后标题保留。原生枚举／查询仍为 3 → 2 → 3 → 3，空间统计与独立文件元数据合计一致。

`go vet`、Go 全套测试、Node 前端测试及 Windows Wails 生产构建通过。没有执行原生桌面交互验收，系统文件选择对话框的交互仅完成编译检查；导入校验与恢复服务已自动化测试。测试没有读取真实用户会话或上传内容。

范围：独立 Windows 本地版，简化的对话管理、完整原始文件备份、移出来源的隐藏、两种恢复，以及空间统计。没有运行或操作真实 Harness 窗口，没有读取凭据、真实消息或真实用户索引。

## 自动化范围

Go 合成测试覆盖原生普通／多帧压缩 v4 文件头与嵌套消息、UTF-8 有限预览、未来代拒绝回退、整个父子组隐藏、独立手动备份、原目录恢复与 ZIP 恢复、文件 SHA256、运行进程拒绝、同名内容冲突、操作中断恢复、危险路径及篡改 ZIP 拒绝、隐藏区实计、硬链接去重、真实稀疏文件、取消与来源切换，以及演示接口的来源固定和跨站请求拒绝。

前端测试验证容量分级、完整目录搜索和隐藏预览的精确提交范围。JavaScript 语法、Go 静态检查与 Windows 原生生产构建单独执行。界面使用 `textContent` 输出会话内容，不执行 HTML 或记录中的指令，不加载远程图片。

## 明确边界

- 本轮没有读取真实会话，也没有对真实数据执行备份、隐藏或恢复。
- 没有原生桌面人工验收；构建与接口检查不宣称窗口交互已测。
- v4 以外格式保留未知提示，不做消息迁移。路径和大小只能描述实际已枚举部分。
- 隐藏要求同卷；ZIP 明文，单批最多 20 GiB／100,000 个文件。
- 逻辑字节按目录项计，磁盘分配按物理身份去重；不包括目录开销，不跟随链接，移动不等于释放空间。

格式依据为本机固定版本程序资源和 [DeepSeek Harness 官方工程](https://github.com/deepseek-ai/deepseek-harness)。Windows 压缩文件分配接口依据 [FILE_COMPRESSION_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_compression_info)。
